# EIGA Design Rules

Apply these rules whenever working on files under `src/components`, `src/app`, or visual assets.

## Composition

The graph/visualization owns the page. Supporting UI should frame it, not compete with it.

Prefer:
- asymmetry over rigid card grids
- editorial hierarchy over dashboard hierarchy
- large breathing room
- quiet surfaces
- strong focal points

## Motion

Motion should explain relationships:
- selection
- focus
- reveal
- navigation
- filtering

Avoid continuous decorative motion, gratuitous parallax, or animations that delay comprehension.

Respect reduced-motion preferences.

## Color

Use a mostly neutral palette with one accent. Color should signal state or emphasis, not classify every graph entity by default.

## Typography

Typography is a primary brand element. Use a distinctive display treatment for major titles and a highly legible sans-serif for UI copy. Avoid novelty fonts.

## Graph readability

At any zoom level, the user should have an answer to: “What am I looking at?”

Do not show every label all the time.
Use opacity, scale, and selective disclosure to establish hierarchy.
